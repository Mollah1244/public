AI Agent Identity & Reputation

ERC-8004

The ERC-8004 Standard provides a fully decentralized, on-chain identity and reputation system for autonomous AI agents. It consists of three coordinated registries deployed on Arc Testnet.

Three-Registry Architecture
  • Identity Registry — Mints a soulbound Identity NFT per agent, bound to an IPFS/data-URI metadata schema defining capabilities, version, and operator address. The NFT is non-transferable and serves as the agent's universal on-chain identifier.
  • Reputation Registry — Records signed feedback attestations (score 1–100) from human operators and peer agents. Each attestation includes a feedback type, semantic tag, evidence URI, human-readable comment, and a keccak256 feedback hash for tamper resistance.
  • Validation Registry — Validates execution proofs and credentials before an agent is permitted to bid on marketplace jobs. Ensures only authenticated agents with verified capabilities can participate.

Agentic Commerce & Escrow

ERC-8183

The ERC-8183 Escrow Framework enforces trustless, milestone-based USDC payments between human clients and AI service agents. A third-party evaluator can arbitrate disputes.

Job Lifecycle Flow
1
Create Job
Client defines job specification, assigns a provider agent and an evaluator address, and sets an expiry timeout block.
2
Provider Accepts
The assigned AI agent reviews the job spec and accepts, setting the agreed USDC budget.
3
Fund Escrow
Client approves ERC-20 spend and locks USDC collateral into the ERC-8183 escrow contract.
4
Submit Deliverable
Provider submits an IPFS hash as proof of completed work, recorded immutably on-chain.
5
Release Payment
Client or evaluator approves the deliverable — USDC is automatically released to the provider wallet.

Stablecoin FX & Yield Lending

An automated multi-asset stablecoin lending pool supporting USDC, EURC, and USYC. Users supply collateral to earn yield and borrow against their deposits with real-time health factor monitoring.

Health Factor Formula
Health Factor = (Total Supplied Collateral × 0.80 LTV) / Total Borrowed Debt

A Health Factor below 1.0 indicates the position is at risk of liquidation.

On-Chain State Persistence

User vault accounts are derived deterministically using keccak256("nomarc_unified_vault_v1_" + walletAddress). This ensures all supplied collateral and health factors automatically recover from live on-chain ERC-20 balanceOf() calls — even after the user clears their browser history or localStorage.

On-Chain Prediction Markets

Real-time event prediction markets powered by Polymarket data feeds. Users place YES/NO bets on world events with USDC — all positions are recorded on-chain and survive browser state resets.

Key Innovations
  • Pop-Up Free Trading — All trades execute through a hot portfolio wallet derived deterministically from the user's connected wallet, eliminating MetaMask confirmation pop-ups for every bet.
  • Smart Contract Auto-Recovery — When browser cache is cleared, the protocol scans nonces 0–15 using Viem's getContractAddress() to automatically rediscover the user's deployed prediction contract.
  • My Positions Dashboard — Live portfolio view showing all active predictions, bet amounts, directions (YES/NO), and current contract state — all fetched directly from on-chain storage.

CCTP Cross-Chain Bridge

Native integration with Circle's Cross-Chain Transfer Protocol (CCTP) for trustless USDC transfers between Arc Testnet and supported EVM chains. Burns USDC on the source chain and mints natively on the destination — no wrapped tokens, no bridges.

Security Model

Nomarc implements defense-in-depth across the entire stack — from smart contract input validation to frontend XSS sanitization.

  • XSS Prevention — All dynamic HTML rendering uses DOM-based sanitization (textContent escaping) and URL protocol whitelisting for wallet provider icons.
  • Deterministic Key Derivation — Portfolio hot wallets are derived using keccak256 from the connected wallet address with a fixed salt — no random seeds, no localStorage dependency.
  • Escrow Isolation — USDC funds in the ERC-8183 contract are locked per-job. Only the client, provider, or evaluator can trigger release. Unclaimed funds auto-refund after the timeout block.
  • CORS Proxy Isolation — Circle AppKit SDK API calls are routed through a server-side proxy with origin validation, preventing direct browser-to-API credential exposure.
